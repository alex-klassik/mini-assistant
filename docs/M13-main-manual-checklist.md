# M13 — ручная проверка Main на живом Outlook

`Main.buildAgentService` (сборка конфига в рабочий `AgentService`) уже
покрыта юнит-тестом `MainTest` — `MockMailChannel` вместо Outlook,
`MockWebServer` вместо реального LLM-провайдера. Но сам `main()`/`pollLoop`
(разбор аргументов командной строки, реальный `OutlookMailChannel`,
бесконечный цикл с `Thread.sleep`, graceful shutdown, `System.exit` при
фатальной ошибке) — как и `OutlookMailChannel` в M11 — принципиально не
воспроизводимы в CI без установленного Outlook. Этот чек-лист проверяет
именно то, что осталось непокрытым `MainTest`.

## Предусловия

Те же, что в `docs/M11-outlook-manual-checklist.md`: Windows, установлен
классический Outlook, пользователь залогинен, `jacob-1.20-x64.dll` на PATH,
Java 8 x64.

Дополнительно для этого чек-листа:
- Скомпилированные классы проекта (`mvn -q compile`) — до сборки fat-jar
  (M14) можно проверять через classpath напрямую.
- Реальный или тестовый LLM-эндпоинт, совместимый с OpenAI Chat Completions
  (либо развёрнутый локально стаб) и рабочий API-ключ в переменной
  окружения, указанной в `apiKeyEnv` конфига.
- HMAC-ключ аудит-журнала в переменной окружения, указанной в `hmacKeyEnv`.
- `config.yaml`, скопированный из `config.example.yaml` в корне репозитория
  и заполненный реальными значениями (`llm.endpoint`, `llm.model`,
  `mail.profile`/`mail.folder`, `store.path`).

## Шаг 1 — валидация аргументов командной строки

1. Запустить `Main` без аргументов (например, через classpath: `java -cp
   target/classes;<зависимости> com.miniassistant.app.Main`).
2. **Ожидаемо:** в stderr печатается понятное сообщение об использовании
   (`Usage: java -jar mini-assistant.jar <config.yaml>`), процесс завершается
   с ненулевым exit code, без стектрейса.
3. Запустить `Main` с путём к несуществующему файлу конфига.
4. **Ожидаемо:** процесс не падает сырым стектрейсом — фатальная ошибка
   логируется структурно (`event=agent_fatal_error error=...`, текст
   исключения пропущен через `PiiMasker`), затем `System.exit(1)`.

## Шаг 2 — полный цикл через Main на живом Outlook

1. Убедиться, что во «Входящих» (или в папке, указанной в `mail.folder`)
   есть хотя бы одно непрочитанное письмо с осмысленным текстом (например,
   «Напомни мне позвонить клиенту завтра в 15:00»).
2. Запустить `Main` с валидным `config.yaml`.
3. **Ожидаемо:** в течение одного цикла опроса приходит ответ на письмо (в
   «Отправленных» появляется `RE:`-ответ), в `store.path` появляются/
   обновляются `seen.txt`, `reminders.json` (если запрос требовал
   `add_reminder`) и `audit.jsonl`.
4. Проверить `audit.jsonl` — построчный JSON с событиями `tool_called`/
   `mail_processed`, содержимое письма (тело) в файле не встречается.
5. Не помечать явно письмо прочитанным между опросами — повторный цикл (по
   истечении `mail.pollSeconds`) не должен породить второй ответ на то же
   письмо (идемпотентность через `SeenStore`, как в M6/M11).

## Шаг 3 — graceful shutdown по Ctrl+C

1. Пока `Main` находится в ожидании (`Thread.sleep` внутри `pollLoop`,
   между циклами опроса), нажать Ctrl+C в консоли.
2. **Ожидаемо:** в логе появляется `event=agent_stopped`, процесс завершается
   быстро (без зависания на неопределённое время) и без стектрейса;
   COM-ресурсы Outlook освобождены (`OutlookMailChannel.close()` в
   try-with-resources сработал — если запустить `Main` заново сразу после,
   он не должен упасть на попытке подключиться к Outlook из-за "залипшего"
   предыдущего COM-объекта).

## Известные ограничения (по прецеденту M11)

- Секции про `SenderEmailAddress`/Exchange Legacy DN и отсутствие цитаты
  исходного письма в ответе — см. `docs/M11-outlook-manual-checklist.md`,
  они не специфичны для `Main` и не повторяются здесь.
